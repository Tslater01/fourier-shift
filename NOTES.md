# NOTES — failures & surprises

- `torchvision.ImageFolder` would assign classes alphabetically (FAKE=0, REAL=1), silently inverting our REAL=0/FAKE=1 convention and every F1/AUROC number. Built the index from an explicit class->label dict instead.
- Windows `spawn` pickles the Dataset into each DataLoader worker, so lambda transforms crash `num_workers>0`. All domain/corruption transforms are classes or `T.Compose` objects built in `__init__`.
- First `--limit` implementation strided over the whole index and returned 2066/1934 instead of 2000/2000 — the stride doesn't divide the per-class blocks evenly. Now strides within each class.
- The `jpeg75` robustness condition is very nearly a no-op: CIFAKE is *already* stored at quality 75, so re-encoding at 75 changes almost nothing (acc 0.9448 vs 0.9443 clean). It is a useful pipeline control but carries no robustness information — consider adding a harsher quality (e.g. jpeg30) if we want a second point on the curve.
- Cross-generator RGB result is *below chance*: acc 0.469, F1 0.057, AUROC 0.4287 on DDPM. The spatial detector does not merely fail to transfer, its ranking is anti-correlated — it confidently calls DDPM fakes "real". Reported unflipped.
- train.py and evaluate.py disagree on test acc by 2/20000 (0.9444 vs 0.9443) for the same checkpoint: train.py sets cudnn.benchmark, evaluate.py does not, so conv algorithm choice under fp16 autocast differs on borderline samples. Cosmetic, but do not report both numbers as if independent.
- CIFAKE REAL and FAKE are encoded identically (JPEG, RGB, 32x32, quality 75, 4:2:0, ~945 bytes), so the dataset is not confounded by compression. DDPM samples are therefore written at exactly q75/4:2:0 — saving PNGs would have made the cross-generator eval a compression detector instead of a generator-fingerprint detector.
- The venv has no `pip` (it is a uv venv); `python -m pip install` fails. Use `uv pip install` with `$env:VIRTUAL_ENV` set.
- DDPM's spectrum sits on the *opposite* side of REAL from CIFAKE's fakes: mean high-frequency (nyquist/mean) ratio is 0.276 for CIFAKE FAKE, 0.203 for REAL, 0.170 for DDPM. An FFT detector that learned "excess HF energy => fake" should therefore misread DDPM fakes as real. Predicts a below-chance cross-generator result for the FFT arm — a two-sided finding, not a bug.
- Windows `spawn` costs ~20-40 s per DataLoader worker pool regardless of dataset size (each worker re-imports torch + sklearn). Three pools made the 2,000-image smoke test take 3.8 min against a 2-min gate while the actual compute was <2 s. Fix: only the train loader gets workers, and only when the split exceeds 10k images. Smoke went 3.8 min -> 98 s.
- Isolated DataLoader benchmarks lied by 13x (4,400 img/s vs 325 img/s in a real epoch): the bench reused a 6k strided subsample that sat warm in the OS page cache. Never size a queue from a microbenchmark that touches fewer files than an epoch does.
- Cold first epoch over 95k files is ~293 s; every later epoch is ~30 s, since the ~120 MB dataset ends up fully page-cached. So a 15-epoch resnet18 run is ~8 min, not the ~73 min the first epoch implied.
- ConvNeXt's first measured step was 4980 ms, which read as "E3/E4 don't fit tonight". It was cudnn autotune on step 1: with warmup excluded it is 74 ms/step, ~5.5 min for the full 3-epoch fine-tune. Always warm up before timing on CUDA.
- ConvNeXt at 128x128/bs64 peaks at 1.73 GB of 8 GB. Raising to bs 128/256 costs 3.0/5.6 GB and is *slower* per image, so the CLAUDE.md bs=64 stands unchanged.
- Raw-magnitude spectra (ablation A1) standardize to a max of ~+39 vs ~+7.5 for log-magnitude: the DC term is a huge outlier without log compression. Predicts A1 trains worse; that's the ablation's point.
